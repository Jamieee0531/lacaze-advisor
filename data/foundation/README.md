# 数据基建（草稿 v0.2）

LACAZE 的业务数据。所有人物、商品、价格、服务和活动均为虚构。
本目录尚未接入运行链路；接入后将取代 `data/catalog/products.json`，以及 case 中手写的活动、服务事实。

## 文件

| 文件 | 内容 | 主键 | 关联 |
|---|---|---|---|
| `clients.json` | 客户身份：称呼、性别、年龄、职业、生日、所属门店、建档日期 | `client_id` | — |
| `purchases.json` | 逐笔消费记录：商品、颜色、日期、成交价、门店 | `purchase_id` | `client_id`、`product_id` |
| `products.json` | 六款商品：定位、价格、资格、配货、尺寸、重量、皮料、开合、内部结构、背法、颜色、能装什么、工艺、保养 | `product_id` | — |
| `services.json` | 门店服务：内容、适用条件、办理方式 | `service_id` | — |
| `policies.json` | 定价、渠道、配货、客户层级规则 | — | — |
| `events.json` | 门店活动：时间、地点、参加范围、内容、可约时段、不包含的权益 | `event_id` | `featured_products` → `product_id` |
| `calendar.json` | 2026–2027 年节日；农历节日已换算成公历 | `date` + `name` | — |

## 约定

1. **一个事实只存一处。** 层级、累计消费、年度消费都由 `purchases.json` 计算，不手工填写。
2. **null 表示不知道，空列表表示确认没有。** 例如 `birthday: null` 表示没有记录生日；一位客户在 `purchases.json` 中没有任何记录，表示确认尚无购买。
3. **ID 用小写英文**，例如 `cl004`、`veronique`、`sv_annual_care`；中文名称只出现在 `name` 字段。
4. **门店统一为 `shanghai_chengyuan`**，即 LACAZE 上海澄园店（虚构）。
5. **偏好、需求、沟通习惯不在这里**，由模型从对话历史中理解，和 `CLIENT_PROFILES.md` 的原有约定一致。

## 刻意不提供的信息

以下信息品牌不会提供给顾问。话术中一旦出现具体内容，即可判定为编造：

- 库存数量、到货时间
- 保值、升值、转售价格
- 折扣、赠品、额外权益
- 其他渠道的价格与真伪判断
